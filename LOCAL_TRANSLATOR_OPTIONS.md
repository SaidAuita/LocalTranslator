# Руководство: Создание компактного локального переводчика (Аналог QTranslate)

Документ подготовлен для выбора архитектуры и стека при создании автономного переводчика для Windows.

---

## 1. Разбор новости о «NLLB 3.3B SALT»

В исходной заметке из сети была допущена путаница в терминологии и моделях:

* **Модель:** [Sunbird/translate-nllb-3.3b-salt](https://huggingface.co/Sunbird/translate-nllb-3.3b-salt) — это дообучение модели Meta NLLB-200 организацией **Sunbird AI** (Уганда). Её фокус — африканские языки (луганда, руньянколе, ачоли и др.) в паре с английским. Для русско-английского перевода она не имеет преимуществ перед оригинальной Meta NLLB.
* **Доступ:** Репозиторий закрыт авторизацией (`gated`, требует подтверждения заявки на Hugging Face).
* **Размер:** Веса выложены в формате FP32 safetensors и весят **13.38 ГБ** (квантованной 4-битной версии в репозитории нет).
* **Движок:** Семейство NLLB — это **Seq2Seq (Encoder-Decoder / M2M-100)**. Популярный движок `llama.cpp` исторически оптимизирован под **Decoder-only** архитектуры (LLaMA, Mistral, Qwen) и нативно NLLB не запускает. Родной скоростной C++ движок для NLLB — это **CTranslate2** (OpenNMT).

**Вывод:** Идея специализированного изолированного переводчика без цензуры и галлюцинаций — идеальна, но использовать нужно либо **оригинальную Meta NLLB-200 через CTranslate2**, либо **компактные LLM (Qwen 2.5) через llama.cpp/Ollama**.

## 2. Сравнение моделей для локального перевода

| Критерий | Вариант 1: Meta NLLB-200 (CTranslate2) *(Рекомендуется)* | Вариант 2: Qwen2.5-3B-Instruct (llama.cpp / Ollama) | Вариант 3: Argos Translate / LibreTranslate |
| :--- | :--- | :--- | :--- |
| **Тип модели** | Специализированный NMT (машинный перевод) | Современная генеративная LLM | Модульный NMT (пакеты языковых пар) |
| **Поддерживаемые языки** | 200 языков (RU, EN, DE, FR, ES, ZH и др.) | Мультиязычная (превосходный RU/EN) | По парам (EN↔RU ~150 МБ на пару) |
| **Потребление памяти** | **600M:** ~600 МБ RAM (INT8)<br>**1.3B:** ~1.4 ГБ RAM (INT8) | **3B (Q4_K_M):** ~2.0 ГБ VRAM/RAM<br>**7B (Q4_K_M):** ~4.5 ГБ | ~300–500 МБ RAM |
| **Галлюцинации и лишний текст** | **0%** (переводит строго исходный текст) | Возможны без жесткого промпта | **0%** |
| **Скорость на CPU** | Сверхбыстро (0.1–0.3 сек на абзац) | Средне (20–40 токенов/сек) | Быстро (0.2–0.5 сек) |
| **Скорость на RTX 3080 Ti** | Мгновенно (< 50 мс) | Мгновенно (80–120 токенов/сек) | Мгновенно |
| **Движок запуска** | Библиотека `ctranslate2` (C++ ядро) | `llama-server.exe` или `Ollama` | Библиотека `argostranslate` |

## 3. Архитектура интерфейса («Опыт QTranslate»)

Классический **QTranslate** был незаменим благодаря бесшовному взаимодействию с Windows. Полноценная локальная реализация должна воспроизводить эту механику:

1. **Фоновая работа в трее:** утилита запускается при старте Windows, висит в System Tray и потребляет минимум ресурсов.
2. **Глобальный хоткей захвата (`Ctrl+Q` или `двойной Ctrl`):**
   * При нажатии утилита симулирует копирование (`Ctrl+C`) текущего выделенного текста в любом приложении (браузер, Telegram, PDF-ридер, Word, IDE).
   * Забирает текст из буфера обмена.
3. **Автоопределение направления:**
   * Если текст на кириллице -> перевод на английский.
   * Если текст на латинице -> перевод на русский (или настраиваемый язык).
4. **Всплывающий Popup у курсора:**
   * Компактное темное окно без тяжелых рамок прямо рядом с местом выделения.
   * Кнопка быстрого копирования перевода в буфер.
5. **Замена выделенного текста на лету (`Ctrl+Shift+Q`):**
   * Переведенный текст сразу вставляется на место исходного (через `Ctrl+V`).

## 4. Варианты реализации приложения

### Путь А: Свой компактный скрипт / приложение (Python + PyQt6)
* **Плюсы:**
  * 100% автономность: один скрипт или скомпилированный `.exe`.
  * Встроенный `ctranslate2` — не нужно ставить сторонние фоновые сервисы и серверы.
  * Точная настройка горячих клавиш, интерфейса и логики всплывающего окна под себя.
* **Стек:** `Python 3.11` + `PyQt6` (для стильного UI) + `keyboard` / `pynput` (глобальные хоткеи) + `ctranslate2` (быстрый инференс).

### Путь Б: Готовая оболочка Pot-App + локальный бэкенд
* **[Pot (Pot-App)](https://pot-app.com/)** — современная open-source утилита на Tauri/Rust, визуально и функционально превосходящая старый QTranslate.
* **Плюсы:** Готовый интерфейс, поддержка плавающего окна, хоткеев, распознавания текста (OCR) и выделения скриншотом.
* **Интеграция:** Умеет отправлять запросы в локальный **Ollama** или **llama.cpp** (OpenAI-compatible API).

### Путь В: Crow Translate
* Легковесный C++/Qt клиент.
* Работает с локальным сервером **LibreTranslate** (на базе Argos Translate).

## 5. Доступные аппаратные ресурсы системы

Текущая конфигурация компьютера:
* **GPU:** NVIDIA GeForce RTX 3080 Ti (12 ГБ VRAM) — позволяет держать модель в видеопамяти и получать перевод за миллисекунды.
* **Окружение:** Python 3.11.9, Git, Windows 11/10 x64.
* **CPU:** Позволяет легко запускать квантованные NLLB-модели даже без задействования видеокарты, если VRAM занята играми или графическими редакторами.

## 6. Что делать, когда вы вернетесь

Выберите предпочтительный сценарий:

1. **«Хочу полностью свое компактное приложение на Python»:**
   * Установим `PyQt6` и `ctranslate2`.
   * Скачаем компактную модель `nllb-200-distilled-600M` (или `1.3B`).
   * Напишем легкий трей-клиент с всплывающим окном по `Ctrl+Q` и автозаменой текста.
2. **«Хочу готовую утилиту Pot-App + локальную модель»:**
   * Установим Pot-App.
   * Настроим подключение к локальной LLM (Qwen 2.5 3B через Ollama или llama.cpp).
3. **«Хочу протестировать качество перевода перед выбором интерфейса»:**
   * Сделаем тестовый CLI-скрипт, подадим несколько сложных предложений/терминов на NLLB и Qwen и сравним результаты.
